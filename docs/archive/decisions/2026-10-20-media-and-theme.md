# Safe images and theme controls — 20 October 2026

Status: local development implementation; production acceptance outstanding.

The owner's request to continue advances the image and appearance portions of
WP-05/06. It does not authorize external Instagram access or change the outstanding
reviews, mail, identity, retention and account decisions.

Image input is restricted to one bounded, single-frame PNG/JPEG/WebP. Decode
actual bytes, apply EXIF orientation, then save a new metadata-free PNG under a
generated UUID key. Never fetch remote image URLs or use an upload's filename as
a storage key. Readability and media safety are checked server-side.
[Pillow image operations](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html)
documents orientation handling; only the installed locked Pillow release is used.

Replacements create immutable new binary files. `MediaAsset.active` selects the
current record; a partial unique constraint protects active item/sequence pairs.
Both the public feed and media database views require active validated media.
Replacing an image revokes its old public URL on the next request. Owner-only
history delivery remains available, including hidden/draft images. Alt-only edits
also preserve the old descriptors in an append-only revision and advance the same
story version used by text/status editing.

Upload authorization, version checks, selection changes, shared quota accounting,
content revisions and safe field-name audit events share a transaction. Cleanup
removes known-uncommitted files. After an ambiguous commit acknowledgement, check
whether the descriptor exists; retain the file when committed or when the check
cannot be completed. This favors an orphan over a missing committed asset.

The global `MediaQuota` row serializes image reservations across workers. Existing
descriptors backfill its usage. Old images remain counted because retention is
unresolved. Defaults are 10 MiB input/output, 20 million pixels and 512 MiB total;
only the operator runtime environment can change the budget. Warnings start at
80%. Streaming upload guards cap temporary writes and reject unauthorized image
upload routes before parsing their bodies. Owner CSRF checks still apply.

Theme settings are a singleton with optimistic version checks and preserved
revisions. Allow only six-digit hex colours and three local font-family choices.
Require 4.5:1 contrast for body, muted and accent colours against both configured
paper and white cards. These are controlled palette checks, not a full WCAG audit.
[WCAG contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
informs these checks.

Public styles are generated by trusted code at a same-origin stylesheet endpoint;
no raw CSS, remote fonts or inline styles are accepted. Uploaded backgrounds are
decorative and appear outside opaque content panels. A public database view gates
background delivery to the validated image selected in the current saved theme.
Removed/replaced backgrounds remain private. Preview tokens contain only validated
palette/font values, expire after ten minutes, require owner authentication and
scope their stylesheet to the preview panel; uploads are not persisted by Preview.

`site_admin` gains INSERT on media/image descriptors, limited active/alt updates,
quota usage updates and theme setting updates. It cannot rewrite storage keys,
delete media/quota rows or alter validated background metadata. `site_public`
receives SELECT only on the new public theme views. Docker's admin image volume
becomes writable while the public mount stays read-only; source mounts stay
read-only. Production no-exec/mount policies and physical monitoring need review.

Migrations preserve existing content. Keep schema `0005` after replacements:
inactive history can legitimately duplicate old sequence numbers, so reinstating
the prior unconditional uniqueness constraint is unsafe. Prefer compatible code
rollback or forward fix. Boundary `0006` can reverse/reapply while preserving
active-only filtering, quota usage, settings and retained records.

Video, thumbnails derived from video, carousel UI, remote provider fallback,
background-image preview before save, settings restoration, physical disk alerts,
reference-aware orphan/retention cleanup, admin translations and browser/accessibility
verification remain later work. The production admin gate remains enabled.
